# Security policy

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in public issues or pull requests.

Use [GitHub private vulnerability reporting](https://github.com/nieve-consulting/lumi/security/advisories/new) if enabled for this repository. If unavailable, contact Nieve through [Nieve’s contact page](https://www.nieveconsulting.com/contact), request a private security reporting channel, and wait for a private route before sending sensitive details.

Include the affected version or commit, a minimal reproduction using fictional data, impact, and any suggested mitigation. Do not include live credentials or other people's personal information. Investigate only systems you own or have permission to assess.

## Maintenance scope

The project does not currently promise a security support window or backports for older releases. Include your exact version; maintainers may ask you to reproduce an issue on current code. Response and remediation times depend on maintainer availability.

## Deployment responsibilities

Operators manage their credentials, access controls, network exposure, backups, updates, and external service configuration. Read [Security](https://docs.lumi.nieve.ai/security), including its operator checklist, [Self-hosting](https://docs.lumi.nieve.ai/self-hosting) and [Data and privacy](https://docs.lumi.nieve.ai/security/data-and-privacy) before exposing an installation publicly.
