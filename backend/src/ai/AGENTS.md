# Prompt caching

OpenAI caches only an exact prompt prefix of at least 1024 tokens, counting tool definitions. When editing agent prompts here:

- Keep each prompt's static instructions first and byte-identical across calls. Put per-call values (conversation state, page title, time, transcripts) after them, never in the middle of the instructions.
- The pre-sales chat call sends: the static system prompt (all state instructions included), the conversation history, then a short per-turn context message. Do not template per-turn values into the system prompt.
- The chat model is always bound to every tool the installation's knowledge sources make available, in a fixed order (`toolsFactory`, with the sources from `src/knowledge.ts`, which stay the same object between edits); per-state restrictions go through the `allowed_tools` tool choice (`allowedToolNames`), not by binding a different tool set. The sources' labels and switches shape the system prompt, the routing prompt and the tool descriptions (e.g. `get_team_members` describes "consultants" under Nieve's labels), so build that text only from the sources object and keep it cached by its identity. The tools plus the system prompt must stay above 1024 tokens even with every structured source off (only `get_company_info`, `webpage_search` and `read_current_page` bound, the last on every turn and only allowed on turns with a page to read), no job openings, no business description, qualification questions or business guidance; that minimal configuration counts about 1,380 tokens with `js-tiktoken` (`o200k_base`, the tool definitions as OpenAI function JSON), so keep edits that shorten it small and recount.
- On GPT-5.6+ a cache read only matches a breakpoint written by an earlier request. The implicit breakpoint covers the conversation so far; the chat call also marks the system prompt with an explicit `prompt_cache_breakpoint` so every conversation shares the tools and the system prompt. That breakpoint is only written while the tool definitions plus the system prompt stay above 1024 tokens, so do not shorten them below it. To check, look at the first chat generation of a new conversation in Langfuse: its `input_cache_read` should roughly match the size of the tools plus the system prompt, and if it stays at zero across new conversations the prefix has dropped below the threshold.
- Helper chains put their instructions in the system message and the per-call values and transcript (`formatTranscript`, which drops tool calls and results) in the human message.
- Our GPT-5.6+ models bill cache writes at 1.25x the input rate and cache reads at 0.1x. Prompts that are never reused (the helper chains: sliding windows, one-off extractions and summaries) use `loadOpenAILLM(config, { promptCache: false })` to skip the write.
- Do not set a per-conversation `prompt_cache_key`: on GPT-5.6+ it only separates cache accounting, so it would stop conversations from sharing the cached system prompt and tools.
- Langfuse records cached input as `input_cache_read` and cache writes as `input_cache_creation` on each generation.
